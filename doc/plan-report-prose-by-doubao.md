# 报告正文改由豆包撰写

决策（用户 2026-09-09）：**正文交给豆包照模板写；图由后端渲染；图的数据一并给豆包；正文数字出错可以接受，读感优先。**

## 与现状的差别

| | 现在 | 改后 |
|---|---|---|
| 正文 | 后端按事实渲染成句（441 字确定文本），豆包只填 4 个 `<<>>` 槽 | 豆包写整段正文 |
| 数字 | 全部来自后端，不可能错 | 豆包写，可能错——**接受** |
| 图 | 后端出语义规格，前端渲染 | 不变 |
| 图位 | 模板里的 `{{chart:id}}` | 不变，仍由后端定位置 |
| 图注 | 后端算出的解读 | **仍由后端算**（图下方那行不交给豆包） |

图注保持确定，是因为它紧贴图、最容易被读者拿去核对；正文放开。

## 给豆包的输入

一次调用产出一节（或整篇，视 token 而定），输入三块：

1. **结构模板**：小节顺序与每节要回答什么，含 `{{chart:id}}` 的位置。豆包按这个结构写，不得增删小节。
2. **事实清单**（JSON）：任务/数据集/排行榜/折间统计/SHAP/验证方式/就绪度 —— 即今天 `build_overview_facts` 算出来的全部内容，外加派生量（倍数、差值、占均值百分比）。
3. **图的数据**：每张图的 `title` + `rows`（悬停里那些字段）+ 后端算好的 `caption`。让它知道图上到底画了什么，正文才能和图对上。

写作约束（提示词）：中文书面语；每句最多两个数字；每段最多三句；不写建议、不评价值不值得；模型名照抄事实清单；上下文没有的不写。

## 不做的事

- **不做数字校验闸门**。用户明确接受数字出错，不因此挡下归档、不逐段回退。
- 仍保留现有的 `integrity_issues` 结构校验（未替换占位符、空括号、孤立标题）——这些是渲染残缺，不是内容判断。

## 唯一的观测点

归档里记一个 `prose_number_mismatches: int`：把豆包正文里的多位数/小数/百分数与事实清单比对，**只计数，不改动、不拦截、不显示给读者**。目的是过一段时间能回答"这条路到底错得多不多"，而不是靠人肉在页面上抓。
