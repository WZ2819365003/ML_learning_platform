# 天翼云增量热更新说明

## 1. 目标与定位

增量热更新用于频繁的小范围界面和 Python 业务逻辑调整。它不重建包含完整机器学习依赖的 Backend 镜像，而是把已提交、已推送的运行时代码同步到现有容器，并在原容器内完成短重启和验证。正常情况下，Backend 更新只产生数秒级中断；Frontend 更新主要耗时为 Vite 构建。

该通道保持生产环境的可控性，不在生产容器中开启 `uvicorn --reload`，也不把宿主机源码永久挂载进容器。

## 2. 更新范围

可以增量更新的内容如下：

- `ml_platform/app/**`：同步到 Backend 和 Celery Worker，随后原地重启两个容器。
- `ml_platform_web/src/**`、`ml_platform_web/public/**`、`ml_platform_web/index.html`：构建新的 `dist`，替换 Frontend 容器中的静态产物，随后原地重启 Frontend。
- 测试、文档和普通脚本：不重启运行时，只推进已部署版本标记。

下列变化会被自动拒绝，必须执行完整部署：

- Python 或 Node.js 依赖文件；
- Alembic 配置或数据库迁移；
- Dockerfile、Compose、Nginx 等容器配置；
- `ml_platform` 中位于 `app/` 之外、可能被训练任务动态调用的运行时文件。

## 3. 使用方法

先提交并推送当前分支，再从本地执行。脚本会从本地生成增量 Git bundle 并通过 SSH 传输，云服务器不需要访问 GitHub：

```bash
DEPLOY_HOST=<服务器地址> \
DEPLOY_PORT=<SSH端口> \
bash scripts/hot-update-cloud.sh
```

首次验证增量通道或需要强制刷新 Backend 时，可以增加 `--force-backend`：

```bash
DEPLOY_HOST=<服务器地址> \
DEPLOY_PORT=<SSH端口> \
bash scripts/hot-update-cloud.sh --force-backend
```

Codex 通过 `tianyiyun.mcp` 操作时，应先把云端仓库快进到目标提交，再调用：

```bash
bash scripts/hot-update-runtime.sh --from <当前运行版本> --to <目标版本>
```

## 4. 验证与回滚

每次增量更新会自动完成以下检查：

1. 校验更新历史是快进关系，并根据变更文件判断是否允许热更新。
2. 保留容器内上一版 Backend 或 Frontend 文件。
3. 等待 Backend、Worker、Frontend 健康状态恢复。
4. 同时验证 Backend 直连健康接口和 Nginx 公网入口。
5. 使用服务器凭据验证登录、当前用户和模型列表接口。
6. 任一步失败时恢复上一版运行时文件并重启对应容器；全部通过后才记录新的运行版本。

完整部署仍由 `scripts/deploy-cloud.sh` 负责，适用于依赖、数据库结构和容器配置变化。
