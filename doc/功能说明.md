# 功能说明（v3.2.4）

> "傻子也会训练模型" 是一个面向非算法用户、覆盖 **数据 → 训练 → 评估 → 部署 → 推理** 全链路的 ML/DL/时序 一体化平台。
> 本文从 5 个功能模块的角度详细介绍每一项可在 UI 上点击使用的能力，以及它在后端的具体实现位置，便于阅读源码、回归测试、产品演示时三方对照。
>
> 全文示例对应版本：`v3.2.4+`。具体演示或测试报告应同时记录 git commit、Docker image digest 与 `/health.version`。

## 1. 机器学习模块（ML）

> "经典 ML"，covers tabular 分类 / 回归任务，依赖 scikit-learn + XGBoost + LightGBM。

### 1.1 数据导入与探查
- **路径**：`/data` 页（[DataManagement.jsx](../ml_platform_web/src/pages/DataManagement.jsx)）
- **能力**：
  - 上传 CSV / XLSX 文件，文件名自动加 12 字 UUID 前缀避免冲突
  - 自动统计行数、列数、每一列的 dtype / null_rate / unique_rate / 取值样本（`columns_info` JSON）
  - 数据预览（前 100 行，分页）
  - 多版本快照：同一数据集的不同清洗版本通过 `dataset_versions` 表追溯
- **后端**：[`data_service.py`](../ml_platform/app/services/data_service.py)，路由 `/api/data/*`

### 1.2 训练任务创建
- **路径**：`/training/config` 页（[TrainingConfig.jsx](../ml_platform_web/src/pages/TrainingConfig.jsx)）
- **支持模型**（在 [`model_registry.py`](../ml_platform/app/core/model_registry.py) 注册）：

| 类型 | 模型 token | 算法 |
|---|---|---|
| 分类 | `random_forest` | scikit-learn RandomForestClassifier |
|  | `xgboost` | XGBoost (`tree_method=hist`) |
|  | `lightgbm` | LightGBM gbdt |
|  | `logistic_regression` | sklearn LogReg + StandardScaler |
|  | `svm` | sklearn SVC（含 `probability=True`） |
|  | `mlp` | sklearn MLPClassifier |
| 回归 | `random_forest_regressor` / `xgboost_regressor` / `lightgbm_regressor` |  |
|  | `linear_regression` / `ridge` / `lasso` / `elasticnet` |  |
|  | `svr` / `mlp_regressor` |  |

- **可配置项**：超参数 JSON 编辑、`test_size`、`cv_folds`、目标列、备注 / 标签
- **后端**：[`training_service.py`](../ml_platform/app/services/training_service.py)、训练器在 [`trainer.py`](../ml_platform/app/core/trainer.py) / [`regression_trainers.py`](../ml_platform/app/core/regression_trainers.py)

### 1.3 训练执行与实时监控
- **路径**：`/training/monitor/:taskId`（[TrainingMonitor.jsx](../ml_platform_web/src/pages/TrainingMonitor.jsx)）
- **执行方式**：异步 background coroutine 派发到 4 worker 的 ThreadPoolExecutor，避免阻塞 FastAPI 事件循环
- **实时通道**：`/ws/logs/{task_id}`（[`websocket.py`](../ml_platform/app/api/websocket.py)），前端订阅后所有 `TrainingLogger.log` 调用 200 ms 内可见；WS 断开时自动降级到 3 秒 HTTP 轮询
- **进度指标**：`TrainingTask.progress` (0-1)、`current_metric`、`status`（PENDING → RUNNING → SUCCESS/FAILED）

### 1.4 结果可视化（Results 页）
- **路径**：`/training/results?taskId=...`（[Results.jsx](../ml_platform_web/src/pages/Results.jsx)）；`/results` 为兼容重定向入口
- **图表与诊断**：
  - **核心指标卡**：accuracy / precision / recall / F1（分类）或 RMSE / MAE / R²（回归）
  - **Confusion Matrix**（分类）
  - **ROC 曲线 + AUC**（二分类 / 多分类 OvR）
  - **PR 曲线 + AP**、**Calibration 曲线 + ECE / Brier**
  - **Threshold 调优表**：扫 0.1..0.9 阈值的 F1/Precision/Recall
  - **Feature Importance**（树模型自带 / 线性模型权重 / KernelExplainer 派生）
  - **学习曲线**：train vs val 的 score-curve
  - **预测分布直方图**（分类概率 / 回归残差）
  - **Per-Class Metrics**（多分类 classification_report）
  - **K-Fold CV 折叠条形图**（如 `cv_folds > 1`）
- **降级策略**：4 张图独立 `Promise.allSettled` 加载，单图 500 不影响其它，错误图显示重试占位
- **后端**：[`viz_service.py`](../ml_platform/app/services/viz_service.py)，路由 `/api/viz/{task_id}/*`

### 1.5 SHAP 可解释性
- **统一入口**：[`shap_service.py::compute_shap_summary`](../ml_platform/app/services/shap_service.py)
- **三档回退**：
  1. `TreeExplainer` —— xgboost / lightgbm / random_forest / gradient_boost / extra_trees 模型直接用，最快最精确
  2. `KernelExplainer` —— 其它可 `predict_proba` 模型，用 50 个背景样本采样
  3. `sklearn.inspection.permutation_importance` —— 兜底，不返回 per-sample shap_values，仅返回 `mean_abs_shap`
- **响应字段**：`{method, base_value, sample_count, feature_names, shap_values?, feature_values?, mean_abs_shap, top_features:[{feature, importance, direction}]}`
- **缓存**：首次计算后写入 `experiment_runs.metrics.shap_*`，并将完整 payload 上传至 MinIO `explanations/{run_id}/shap_summary.json`
- **NumPy 2.0 兼容**：v3.2.4 升级 `shap==0.46.0`，所有数组 `astype(np.float64)` 序列化

## 2. 深度学习模块（DL）

> 用于 tabular DL 实验，主打"零代码尝试 MLP / LSTM / 1D-CNN / Transformer"。

### 2.1 DL 模型注册
- **注册表**：[`dl_registry.py`](../ml_platform/app/core/dl_registry.py)
- **模型实现**：[`ml_platform/app/core/dl_models/`](../ml_platform/app/core/dl_models/)

| token | 文件 | 适用 |
|---|---|---|
| `mlp_dl` | `mlp_dl.py` | 通用 tabular，3-5 层全连接 |
| `lstm` | `lstm.py` | 序列样本（自动 reshape） |
| `cnn1d` | `cnn1d.py` | 1D 卷积，sliding window |
| `transformer` | `transformer.py` | 4 头 MultiHeadSelfAttention |

### 2.2 配置编辑器（DLConfigPanel）
- **组件**：[DLConfigPanel.jsx](../ml_platform_web/src/components/workbench/DLConfigPanel.jsx)
- **三段配置**（持久化为 `DLTrainingTask.{arch_config, opt_config, train_config}` JSON）：
  - `arch`：层数、隐藏维度、激活函数、dropout、注意力头数
  - `opt`：optimizer（Adam/SGD/AdamW）、学习率、weight_decay、scheduler（cosine/step/plateau）
  - `train`：batch_size、epochs、early_stopping patience、val_split、device（cpu/cuda）
- 新建 DL 任务时调用 `build_default_dl_config(model_id)` 取默认值

### 2.3 训练监控（DL）
- **路径**：`/dl/monitor/:taskId`（[DLMonitor.jsx](../ml_platform_web/src/pages/DLMonitor.jsx)）
- **能力**：
  - **实时 epoch 表**：每个 epoch 的 train_loss / val_loss / val_acc / val_rmse / val_mae / lr，写入 `dl_training_epochs` 表，UI 通过 WS 增量推送
  - **任务类型感知列**：分类显示 `val_acc/val_f1`、回归显示 `val_rmse/val_mae`
  - **训练曲线**：[TrainingViz.jsx](../ml_platform_web/src/components/workbench/TrainingViz.jsx) ECharts multi-metric line chart
  - **Card maxHeight=560**，训练全程页面高度稳定，不随行数跳动
- **后端**：[`dl_service.py`](../ml_platform/app/services/dl_service.py)、训练器 [`dl_trainer.py`](../ml_platform/app/core/dl_trainer.py)

### 2.4 结果（DLResults）
- **路径**：`/dl/results/:taskId`（[DLResults.jsx](../ml_platform_web/src/pages/DLResults.jsx)）
- **分类**：epoch 曲线 + 测试集混淆矩阵 + ROC + classification_report
- **回归**：epoch 曲线 + 残差直方图 + 预测 vs 实际散点
- **history 动态系列**：`buildHistoryOption()` 按 history dict 实际存在的 key 画线，不会出现"恒为 0 的 F1"线

### 2.5 DL 部署
- 同 ML 部署逻辑，模型保存为 `.pt`（state_dict）+ `.scaler.joblib`（特征 StandardScaler），部署后通过 `/api/inference/{deployment_id}` 提供推理

## 3. 时序任务模块（Time Series）

> 基于 Amazon Chronos T5 的零样本时序预测 + 自带 LSTM/TCN/Transformer 训练通道。

### 3.1 部署管理（TS Deployment）
- **路径**：`/ts/tasks`、`/ts/tasks/new`（[TSTasks.jsx](../ml_platform_web/src/pages/TSTasks.jsx) / [TSConfig.jsx](../ml_platform_web/src/pages/TSConfig.jsx)）；`/timesfm` 与 `/ts/config` 为兼容重定向入口
- **支持后端模型**：
  - `amazon/chronos-t5-tiny` / `small` / `base` / `large`（HuggingFace 自动下载）
- **后端**：[`chronos_service.py`](../ml_platform/app/services/chronos_service.py) + [`timesfm_service.py`](../ml_platform/app/services/timesfm_service.py)
- **持久化**：`ts_deployments` 表

### 3.2 预测任务
- **路径**：`/ts/tasks/:taskId`、`/ts/monitor/:taskId`、`/ts/results/:taskId`（[TSMonitor.jsx](../ml_platform_web/src/pages/TSMonitor.jsx) / [TSResults.jsx](../ml_platform_web/src/pages/TSResults.jsx)）
- **流程**：选择数据集 → 指定 `time_column` + `value_column` → 设置 `horizon`（预测步数）+ `frequency`（D/H/T/S/M/Q/Y/W）→ 选模型 → 异步执行 → 写入 `ts_forecast_tasks.result`
- **结果可视化**：历史 + 预测拼接折线图、80% / 95% 置信区间带、预测点表格
- **表单校验**（v3.1.2 修复）：
  - `value_column` 候选过滤：仅显示 numeric dtype 且 `unique_rate < 0.9` 的列（剔除 ID 列）
  - `time_column` 自动从 datetime dtype 或 `time/date/timestamp/ds` 命名启发式中选中
  - `frequency` 限制为 pandas 标准频率字符串

### 3.3 自训练时序（V3 集成尚未完成）
- 在 V3 平台中跑 LSTM / TCN / Transformer 的能力是 v3.x 后续版本目标，当前版本时序仅支持 Chronos 零样本推理 + V2 工作台训练

## 4. 模型管理与部署模块

### 4.1 模型管理（Model Management）
- **路径**：`/models`（[ModelManagement.jsx](../ml_platform_web/src/pages/ModelManagement.jsx)）
- **统一视图**：
  - ML 模型（来自 `training_tasks.status='SUCCESS'`）
  - DL 模型（来自 `dl_training_tasks.status='SUCCESS'`）
  - V3 Run（来自 `experiment_runs.status='SUCCESS'`）
  - TS 部署（来自 `ts_deployments`）
- **能力**：
  - 元数据浏览：模型类型、训练数据集、关键指标、训练时间、模型文件大小
  - 标签管理：基于 `model_tag_library` 表的多维度标签（类别/规模/目的/领域/数据类型 5 个 dimension），支持自定义颜色
  - 备注（notes）编辑
  - 删除：软删除策略（保留训练记录、删除 model artifact + MinIO 副本）
  - 跳转：「查看结果可视化」→ Results 页、「部署上线」→ ModelDeploy
- **后端**：[`model_asset_service.py`](../ml_platform/app/services/model_asset_service.py)，路由 `/api/models/*`

### 4.2 模型部署（ModelDeploy）
- **路径**：`/deploy?taskId=...`（[ModelDeploy.jsx](../ml_platform_web/src/pages/ModelDeploy.jsx)）
- **三类部署**：

| 类型 | 部署表 | 推理路由 | 说明 |
|---|---|---|---|
| ML | `model_deployments` | `POST /inference/ml/{deployment_id}` | 上传 CSV 批量推理或 JSON 单条 |
| DL | `dl_model_deployments` | `POST /inference/dl/{deployment_id}` | 自动加载 `.pt` + 特征 scaler |
| 时序 | `ts_deployments` | `POST /inference/ts/{deployment_id}` | Chronos 零样本，传 `context` 数组 |

- **生命周期**：active → paused → archived；每次推理 `request_count` +1
- **批量推理**：`max_batch_size` 限制（默认 100），超量返回 413
- **响应**：分类同时返回 `predictions` + `probabilities`（如模型支持 `predict_proba`），回归仅 `predictions`
- **后端**：[`deploy_service.py`](../ml_platform/app/services/deploy_service.py) + [`prediction_service.py`](../ml_platform/app/services/prediction_service.py)

## 5. V3 建模工作台

> 这是 v3 系列的核心。V3 把"挑模型 + 调参 + 跑实验 + 看结果"重构为一条统一的 **ModelingTask → PlatformExperiment → ExperimentRun** 流水线。

### 5.1 顶层组织：建模任务（ModelingTask）
- **路径**：`/v3/tasks`（[ModelingTasks.jsx](../ml_platform_web/src/pages/ModelingTasks.jsx)）
- **概念**：一个 ModelingTask = 一个建模目标，例如 *"在 customer_v3 数据集上预测 churn"*。它绑定一个数据集 + 目标列 + objective_metric + objective_direction，在其下可以反复地以不同策略发起实验批次。
- **状态机**：`CREATED → RUNNING → COMPLETED | FAILED | ARCHIVED`
- **新建表单**：name、dataset_id、target_column、task_type、objective_metric、objective_direction
- **后端**：[`modeling_task_service.py`](../ml_platform/app/services/modeling_task_service.py)，路由 `/api/v3/tasks/*`

### 5.2 实验批次（PlatformExperiment）& 三种策略
- **入口**：在 ModelingTaskDetail 页 → `实验编排` Tab → 「新建实验批次」按钮 → [ExperimentBatchModal.jsx](../ml_platform_web/src/components/workbench/ExperimentBatchModal.jsx)
- **三种 strategy_type**（[`tuning_service.py`](../ml_platform/app/services/tuning_service.py)）：

| 策略 | 说明 | 产生 Run 数 |
|---|---|---|
| `baseline` | 直接用各模型默认 / 用户填写的固定超参一次性跑通 | `len(selected_models)` |
| `grid_search` | 笛卡尔积展开 `search_space`，所有组合都跑 | `Σmodel ∏param len(values)` |
| `bayesian_search` | Optuna TPE 采样器，按 `budget.max_trials` 跑 | `len(models) × max_trials` |

- **search_space 格式**：
  - 网格（grid_search）：`{model_token: {param: [v1, v2, v3]}}`
  - 贝叶斯（bayesian_search）：`{model_token: {param: {type:"int|float|categorical", low, high, step?, choices?}}}`
- **budget_config**：`{max_trials, timeout_minutes, cv_folds, test_size, n_trials_per_model, random_state}`

### 5.3 训练方案（TrainingPlan）—— 可复用配方
- **路径**：`/v3/training-plans`（[TrainingPlans.jsx](../ml_platform_web/src/pages/TrainingPlans.jsx)）
- **价值**：把 `(strategy + selected_models + search_space + dl_config + budget + eval_metrics)` 命名后保存，下次新建实验批次直接选方案预填表单
- **`model_family`**：`ml | dl | mixed` —— mixed 方案里每个 token 在派发时按注册表自动判断族归属
- **versioning**：每次编辑 plan，`version` +1；ModelingTask 绑定时把 plan_id + version + 完整 payload 写进 `training_plan_snapshot`，保证历史 run 可重现
- **预估提示**：保存前 UI Tooltip 实时显示"该方案将产生 N 个 Run"，>50 时红色警告
- **后端**：[`training_plan_service.py`](../ml_platform/app/services/training_plan_service.py)

### 5.4 ModelingTaskDetail 页（[ModelingTaskDetail.jsx](../ml_platform_web/src/pages/ModelingTaskDetail.jsx)）
共 5 个 Tab：

| Tab | 说明 |
|---|---|
| **概览** | 任务画像 + 排行榜 + Best Run 卡 + ProgressTree（DAG 可视化） |
| **实验编排** | 列出所有 PlatformExperiment（批次），可新建 / 暂停 / 复制 |
| **Run 对比** | 跨批次的 ExperimentRun 矩阵，按 `objective_metric` 排序，可勾选多 run 并排比较 |
| **策略对比** | 三卡（Baseline Best / Grid Best / Bayesian Best）+ ECharts 箱线图 + 排行榜表 |
| **诊断中心** | 跨任务孤立 run 列表 + Error Boundary 包裹的 RunInspector 入口 |

### 5.5 RunInspector（深度看一次训练）
- **组件**：[RunInspector.jsx](../ml_platform_web/src/components/workbench/RunInspector.jsx)（Drawer 弹出）
- **5 个 tab**：

| tab | 内容 | 数据源 |
|---|---|---|
| 概览 | 关键指标卡 + 参数 JSON + diagnose narrative（过拟合/欠拟合/失败归因） | `experiment_runs` + `run_diagnosis_service` |
| 训练可视化 | 复用 `<TrainingHistoryChart>` 画 epoch / fold 曲线 | `metrics.history` |
| 上下文 | `<Descriptions>` 解释 dataset_name / task_type / features / class_balance / split_seed | `inspector` 端点合成 |
| 日志 | 按 ERROR/WARNING/INFO 分色 + 关键字搜索 + "下载完整日志" | `training_logs` |
| SHAP | `<ShapView>`：method 标签（tree/kernel/permutation）+ base_value / sample_count + summary plot + waterfall + top-3 解释语 | `shap_service` |

- **后端**：[`platform_runs.py`](../ml_platform/app/api/routes/platform_runs.py)，`GET /api/platform/runs/{run_id}/{inspector|shap|viz/...}`

### 5.6 自动诊断
- **服务**：[`run_diagnosis_service.py`](../ml_platform/app/services/run_diagnosis_service.py)
- **输出**：`{overfit_score, failure_reason, param_impact, best_reason, narrative}`
- **逻辑**：
  - **过拟合检测**：`(train - val) / val > 0.15` 判过拟合
  - **失败归因**：扫日志 ERROR 行，按字典映射成中文原因
  - **参数影响**：sibling runs 的 metric ~ params 简单线性回归，找出正负贡献最大的 2 个超参
  - **叙事**：模板生成"该 run 为 X 策略下 Y 模型，metric 为 Z，相对同批次 ±n%。主要影响参数 ..."

### 5.7 跨任务 Run 视图（V3Runs）
- **路径**：`/v3/runs`（[V3Runs.jsx](../ml_platform_web/src/pages/V3Runs.jsx)）
- 扁平列出所有 run（不限定 modeling_task），用于做"出问题的 run 在哪"的快速检索
- 后端 [`v3_runs.py`](../ml_platform/app/api/routes/v3_runs.py)

### 5.8 任务中心（TaskCenter）
- **路径**：`/tasks`（[TaskCenter.jsx](../ml_platform_web/src/pages/TaskCenter.jsx)）
- **两种视图**：
  - **HierarchicalView**：ModelingTask → PlatformExperiment → ExperimentRun → PlatformTask 四层树
  - **FlatView**：扁平地列所有 PlatformTask（含孤立任务，即没有挂在 ModelingTask 下的 legacy/V2 兼容任务）
- **OrphanTaskDetailDrawer**：孤立任务的详情 Drawer，复用日志/指标/SHAP 等

### 5.9 Progress Tree（DAG 可视化）
- **组件**：[ProgressTree.jsx](../ml_platform_web/src/components/workbench/ProgressTree.jsx)
- **服务**：[`progress_tree_service.py`](../ml_platform/app/services/progress_tree_service.py)
- 把整个 ModelingTask 的执行图（experiment 节点 → run 节点 → platform_task 节点）渲染成一棵带状态色的树

## 6. 全局支撑能力

### 6.1 异步任务调度
- **当前**：`InProcessScheduler` —— FastAPI background coroutine + ThreadPoolExecutor (4 workers)
- **未来**：`CeleryScheduler`（v3.x roadmap），`PlatformTask.depends_on` 字段是为 DAG gating 预留的；目前 InProcess 模式忽略依赖

### 6.2 实时通信
- **EventBus**：进程内 pub/sub（[`logger.py::EventBus`](../ml_platform/app/core/logger.py)），不依赖 Redis
- **WebSocket 端点**（[`websocket.py`](../ml_platform/app/api/websocket.py)）：
  - `/ws/training/{task_id}` —— ML 任务进度
  - `/ws/logs/{task_id}` —— 通用日志流
  - `/ws/dl/{task_id}` —— DL epoch 增量
  - `/ws/ts/{task_id}` —— 时序任务进度

### 6.3 实验追踪
- **MLflow Tracking** —— SQLite backend (`/storage/mlflow.db`)，每个 run 自动记录 params / metrics / artifacts
- 通过 `MLFLOW_TRACKING_URI` 环境变量切换到外部 MLflow Server

### 6.4 数据集版本（DatasetVersion）
- 每次数据预处理 / 增量数据导入会生成新的 `dataset_versions` 记录，`schema_hash` 用于检测 schema 漂移；`parent_version_id` 形成版本树

### 6.5 错误隔离
- 前端：所有 ECharts 图表用 `Promise.allSettled` 并发加载，单图失败不影响其它；RunInspector 外包 `<ErrorBoundary>` 防止 JS 异常炸整页
- 后端：`shap_service` 三档 fallback；viz 端点逐图独立 try/except；training_service 失败时把 traceback 截 1KB 写入 `error_message` 字段

### 6.6 国际化
- UI 主语言：简体中文。Tooltip / 表头 / 错误消息均直接以中文存在源码中（短期内不打算 i18n）
