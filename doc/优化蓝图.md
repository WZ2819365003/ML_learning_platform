## A. 生产化与可靠性

### A1 · DB 连接池保活（🔴 P0，0.5d）
- **现状**：`create_async_engine(DATABASE_URL, echo=False, future=True)`（[database.py:44](../ml_platform/app/models/database.py#L44)）无 `pool_pre_ping` / `pool_recycle`。MySQL `wait_timeout` 关掉空闲连接后，池里残留陈旧连接 → **空闲一段时间后首个请求 500**（本项目已复现）。
- **目标**：空闲后首请求不再 500。
- **做法**：`create_async_engine(DATABASE_URL, pool_pre_ping=True, pool_recycle=1800, pool_size=10, max_overflow=20, echo=False, future=True)`；SQLite 分支忽略池参数。
- **验收**：连接空闲 > MySQL `wait_timeout` 后连续请求 200；加一条集成测试模拟断连恢复。
- **工作量**：0.5 人日。

### A2 · 部署/推理 URL 去硬编码（🔴 P0，0.5d）
- **现状**：`base = "http://127.0.0.1:8000"`（[deploy_service.py:88](../ml_platform/app/services/deploy_service.py#L88)）拼推理 URL。上云后返回给前端/调用方的 predict/result URL 全是错的。
- **目标**：部署返回的 endpoint 在任何部署环境都正确。
- **做法**：从 `settings`（`.env` 的 `PUBLIC_BASE_URL`，缺省相对路径 `/inference/...`）取；前端本就走相对 `/inference` 代理，返回相对路径即可。
- **验收**：本地 / docker / 云 三处部署，predict URL 均可直接调通。
- **工作量**：0.5 人日。

### A3 · 代码执行器沙箱 + 超时（🔴 P0，2-3d）
- **现状**：`config_exec_service` / `data_pipeline_service` 用受限 builtins（挡了 `import`），但**同步 `exec` 跑在 FastAPI 事件循环里**——用户写 `while True` 就能**卡死整个后端**；data pipeline 注入 `pd`/`np`，理论上可经其 I/O 能力摸文件系统。
- **目标**：用户代码不能阻塞主进程、不能越权访问宿主。
- **做法**：① 移到**子进程**执行（`ProcessPoolExecutor` 或独立 `subprocess`），带 **wall-clock 超时 + 内存上限**（`resource.setrlimit`）；② 进一步隔离用容器/`nsjail`/`RestrictedPython`；③ 输出通过序列化回传，异常结构化回传。**注意**：这是「用户自有平台的便利功能」，联网/多用户前此项为**硬门槛**。
- **验收**：死循环代码在 N 秒被杀且返回可读错误；`open('/etc/passwd')` 被拒；正常 config/pipeline 仍通。
- **工作量**：2-3 人日。

### A4 · 训练持久化（TD-1，🟠 P1，5-8d，触发条件到再做）
- **现状**：训练走 `asyncio.create_task` 进程内执行，`Scheduler/Celery` 抽象是摆设（见 [TECH_DEBT.md](./TECH_DEBT.md)）。backend 重启 → 跑着的训练全丢。梳理后工作流成主线，暴露面更大。
- **目标**：backend 重启不杀训练；worker 可横向扩展；重活不阻塞事件循环。
- **做法**：按 TECH_DEBT 已列的 6 步（5 条提交路径改 `get_scheduler().submit`、回写语义搬到 celery 回调、Optuna 切 RDBStorage、V3 logs mirror 重接线、测试加 polling、错误传播）。
- **触发条件**：用户报「重启杀训练」/ 单机并发 >4 / 上 GPU / 多机部署（任一命中即还债）。
- **工作量**：5-8 人日。

### A5 · auth 网关纳入仓库（🟠 P1，2d）
- **现状**：线上有 `ml_platform_auth` 鉴权网关（nginx `auth_request` + JWT），**仓库里没有**——本地/线上行为不一致，新人本地跑不出鉴权。
- **做法**：把 auth 服务源码、compose 片段、nginx 配置纳入 `docker/`；`.env.example` 补 `AUTH_*`；文档说明本地默认关/开。
- **验收**：`docker compose up` 起出带鉴权的完整栈；仓库 checkout 即可复现线上拓扑。
- **工作量**：2 人日。

## B. 评估方法学与算法可信度（不含预处理）

### B1 · 调参/评估的选择偏差（🔴 P0，2-3d）
- **现状**：grid/bayesian 按 CV 选最优超参。需审计**上报的 objective_value 是否就是那份「用于选择」的 CV 分数**——若是，则存在**乐观偏差**（selection bias），模型间/策略间对比被系统性高估。trainer 用 `StratifiedKFold`（[trainer.py:35](../ml_platform/app/core/trainer.py#L35)）+ 单次 `train_test_split`（[training_service.py:93](../ml_platform/app/services/training_service.py#L93)）。
- **目标**：上报指标来自**未参与超参选择**的数据。
- **做法**：① 简版——始终保留一份**从未进入调参**的 hold-out test，tuning 只在 train 上做 CV，最终指标在 test 上算并作为对比口径；② 严版——**嵌套 CV**（外层评估、内层选参）。UI 上明确标注「该分数为 test / 嵌套CV，非选参分数」。
- **验收**：同一模型「选参分」与「上报分」在文档/接口里可区分；对比页口径统一。
- **工作量**：2-3 人日。

### B2 · 「公平对比」升级（🟠 P1，3-4d）
- **现状**：多模型对比（`ModelComparison` + `buildComparisonVM`）已能并排指标 + 按模型取最优 trial 的柱状图；但**只给点估计**，缺方差/成本维度。小数据集（iris 150 行）单次 split 方差大，"谁最优"结论不稳。
- **目标**：让"选最优"带统计与成本依据。
- **做法**：`ComparisonVM` 扩展 `cv_mean / cv_std / train_seconds / model_size_bytes`；对比表加这几列，柱状图叠加**误差棒（±std）**；`StrategyCompareTab` 的五数概括思路推广到模型维度；可选加**成对显著性提示**（如 CV 折上的配对差）。
- **验收**：对比页每个模型显示 均值±方差 + 训练耗时 + 模型大小；两个接近模型能看出"差异是否稳定"。
- **工作量**：3-4 人日（后端 run 需补 duration/size 字段 + adapter/组件改）。

### B3 · 指标契约标准化（🟠 P1，1-2d）
- **现状**：`model_registry` 已标 `class_weight_support` 等能力位；但"是否支持 `predict_proba` / SHAP tree path / 部署推理 / 批量预测"这些能力标签尚未标准化（[todo.md](./todo.md) P1 已列）。
- **做法**：注册表补齐能力标签；前端按标签决定是否显示 ROC/SHAP/部署按钮（避免对不支持的模型显示无效操作）。
- **验收**：新增模型只填标签即可正确联动 UI；加 registry 契约测试。
- **工作量**：1-2 人日。

## C. 抽象收敛与技术债

### C1 · 统一两套实验系统（🟠 P1，3-5d）
- **现状**：`platformExperimentsApi`（旧 `/platform/experiments`）与 `modelingTaskApi`（新 `/v3/tasks`）并存；梳理只下线了旧「实验管理」页面，但 **SHAP（`ShapView`）仍依赖旧 API**。
- **目标**：单一实验抽象，退役旧系统。
- **做法**：把 `ShapView` 的 explain 触发/读取迁到 `v3RunsApi`（或 `modelingTaskApi`）；确认 `ExperimentRedirect` 之外无旧 API 消费者后，删 `platformExperimentsApi` + 旧路由 + `Experiments.jsx`/`TaskCenter.jsx` 死文件。
- **验收**：全仓无 `platformExperimentsApi` 引用；SHAP 正常；死页面删除。
- **工作量**：3-5 人日。

### C2 · domain 关联显式化（🟠 P1，2-3d）
- **现状**：run→可部署模型要从 `PlatformTask.payload_ref` **字符串解析** `train:{id}` / `dl_train:{id}`（`_resolve_domain_ref`）——约定式、脆，格式一改全断。
- **目标**：run 与其 domain TrainingTask/DLTrainingTask 用**显式外键/字段**关联。
- **做法**：`ExperimentRun` 加 `domain_task_id` + `family` 列（写入时落库），解析函数退化为兼容旧数据的 fallback；配 migration（见 C3）。
- **验收**：新 run 直接读字段拿到 domain id；旧数据仍可解析；桥接单测覆盖两路。
- **工作量**：2-3 人日。

### C3 · 引入 Alembic migration（🟠 P1，2d）
- **现状**：schema 靠 `Base.metadata.create_all`，无正式 migration → 运行库与代码模型漂移、加列难。
- **做法**：接 Alembic，为现有 schema 生成 baseline revision；此后加列（如 C2 的 domain 字段）走 migration；CI 校验「模型与 migration 一致」。
- **验收**：`alembic upgrade head` 从空库建出完整 schema；改模型忘写 migration 时 CI 报警。
- **工作量**：2 人日。

## D. 测试与质量门禁

### D1 · 修复并硬化 CI 三门禁（🟠 P1，2-3d）
- **现状**：`npm run lint` 之前无配置（本项目已补 `.eslintrc.cjs`）；一批旧 Playwright（`v3-workbench` / `v3-runs-page` / `v3-strategies-uiplus` / `v3_2-smoke`）因 IA/tab 更名会失效；后端 237 测试较好但前端 E2E/lint 未进硬门禁。
- **做法**：① 更新失效 Playwright 断言到新 IA（建模分组 / 运行诊断 / 模型对比 / 调参策略）；② CI 串起 `pytest` + `vitest` + `eslint --max-warnings 0`（先对新增/改动文件强制 0 error，存量 warning 分批清）+ 关键 Playwright gate。
- **验收**：CI 上三门禁全绿且阻断合并。
- **工作量**：2-3 人日。

### D2 · 前端单测扩面（🟢 P1，持续）
- **现状**：已有 `buildComparisonVM` 5 单测 + vitest 基建；覆盖仅点状。
- **做法**：对纯逻辑/hook 优先补测（`useDeployRun` 护栏、workflow 步骤状态机、config payload 组装）；组件用 RTL 补关键交互。
- **验收**：核心 utils/hooks 覆盖率 > 70%。
- **工作量**：持续投入。

### D3 · 注册表契约测试（🟢 P1，1d）
- **现状**：[todo.md](./todo.md) P1 已提「registry contract test 保证 modal/调度/资产页用同一 token」，尚未落地。
- **做法**：加测试断言每个注册模型的 `token/family/task_type/params schema/训练入口/预测入口` 齐备且前后端一致。
- **验收**：新增模型缺字段时测试失败。
- **工作量**：1 人日。

## E. 产品与算法差异化（季度级）

### E1 · 自动化建模（🟡 P2，2-4 周）
- **契合定位**：「傻子也会训练模型」——用户给数据集 + 目标列，平台**自动推荐候选模型 + 预算内跑对照 + 给出最优**。
- **做法**：基于 model_registry 做**一键 AutoML**（按 task_type/数据规模选候选、`grid/bayesian` 预算控制：全局最大 run 数 / 单模型最大 trial / 超时 / 并发，见 [todo.md](./todo.md) P2）；产出直接进 `ModelComparison`。
- **验收**：非算法用户一键得到「已排序的多模型对比 + 可部署最优」。
- **依赖**：B1（评估口径）、A4（并发调度）。

### E2 · 集成与联合训练（🟡 P2，spec 已提）
- **现状**：混合策略 tab 已能 ML+DL 一批对照；spec 里预留了**残差网络 / 联合训练 / Stacking**。
- **做法**：在 B2「公平对比」地基上加 **Stacking/Voting 集成**（用已有 run 的预测做 meta-learner）、DL 联合训练策略作为新的 `strategy_type`（只实现策略层，不改主流程，见 [todo.md](./todo.md) P2 契约）。
- **验收**：集成模型作为一个"模型"进对比，指标可比。

### E3 · 模型 / 数据漂移监控（🟡 P2，2-3 周）
- **现状**：[todo.md](./todo.md) P4 提到漂移入口尚无。
- **做法**：部署后记录线上推理输入分布，与训练集分布对比（PSI/KS），阈值告警；模型卡展示线上输入漂移。
- **验收**：部署详情页可看输入分布漂移趋势 + 告警。

### E4 · 权限 / 审计 / 项目空间隔离（🟡 P2，与 A5 联动）
- **现状**：全系统无权限（[todo.md](./todo.md) P4），多人共享互相覆盖任务。
- **做法**：在 A5 的 auth 基础上加 RBAC + 项目空间（task/dataset/deployment 归属 project）+ 操作审计。
- **验收**：多人各自空间隔离，越权被拒，关键操作留痕。

## 依赖关系（建议实施次序）

```
A1 A2  ──►  可安全上云
A3     ──►  执行器可对外
B1     ──►  B2 公平对比  ──►  E1 自动化建模 ──► E2 集成/联合训练
C3(migration) ──► C2(domain 字段)
A5(auth 入仓)  ──► E4(权限隔离)
D1(门禁) 贯穿全程
A4(TD-1) 视上线并发/多机触发条件
```

**一句话**：先做 A1/A2/A3 让平台「能安全上云、不被用户代码搞挂」，同时做 B1/B2 让「多模型对比」从好看变可信；中期收敛抽象与门禁（C/D）；长期押注「自动化建模 + 公平对比 + 集成」这条差异化主线（E1/E2）。
