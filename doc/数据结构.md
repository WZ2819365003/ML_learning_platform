>
> 字段类型基于 [`ml_platform/app/models/database.py`](../ml_platform/app/models/database.py) 的 SQLAlchemy 声明（MySQL dialect）。

## 1. MySQL 数据表

- 数据库：`ml_platform`（utf8mb4 / utf8mb4_unicode_ci）
- 实例：Docker Compose 服务 `mysql:3306`，宿主机端口 `3307`
- 连接 URL：`mysql+aiomysql://root:123456@mysql:3306/ml_platform`（容器内）

### 1.1 数据资产族

#### `datasets` —— 用户上传的原始数据集

| 列 | 类型 | 说明 |
|---|---|---|
| `id` | VARCHAR(36) PK | UUID |

## 2. MinIO 对象存储

- 服务：Docker `minio:9000`（Web Console `9001`）
- Bucket：**`ml-platform`**（首次启动自动创建）
- 凭证：`mlplatform / mlplatform123`
- 客户端：[`object_storage.py`](../ml_platform/app/services/object_storage.py)（boto3 + s3v4 签名）

| Prefix | 内容 | 写入方 | 消费方 |
|---|---|---|---|
| `models/` | ML 模型 `{task_id}.joblib`、DL `dl_{task_id}.pt` + `.pt.scaler.joblib` | `training_service` / `dl_service` 训练完成后调用 `upload_training_artifacts` | 推理服务 / 模型管理页下载 |
| `logs/` | 纯文本 `{task_id}.log` 与 `{task_id}_metrics.json` | `TrainingLogger.flush()` | "下载完整日志"按钮、Run Inspector 日志 tab |
| `explanations/` | `{run_id}/shap_summary.json` —— SHAP 完整 payload（含 per-sample shap_values） | `shap_service.compute_shap_summary` 首次计算后 | RunInspector SHAP tab、Results 页 SHAP summary |
| `uploads/`（可选） | 大数据集冷备份 | 数据上传服务（如开启 S3_ENABLED） | 数据预览 / 训练数据加载 |

> `S3_ENABLED=false` 时所有上传 silently no-op；本地 `storage/` 目录是兜底持久化层。

## 3. Redis

- 服务：Docker `redis:6379`，appendonly 持久化
- 当前用途：**预留**

平台目前的实时通道（WebSocket pub/sub）使用 **进程内 EventBus**（[`logger.py::EventBus`](../ml_platform/app/core/logger.py)），不依赖 Redis。Redis 服务在 docker-compose 中提供是为了下面三类用途的未来扩展：

| 用途 | 触发条件 |
|---|---|
| Celery broker + result backend | 切换 `scheduler_mode=celery`（v3.x roadmap），用于多 worker / 多机部署 |
| 跨 worker EventBus | 多 backend 实例时把 in-process pub/sub 升级成 Redis pub/sub |
| 短时缓存 | 数据集 columns_info / 排行榜快照等高频读热点 |

环境变量 `REDIS_URL=redis://redis:6379/0`，DB 0 当前空置。

## 4. MLflow Tracking

- Backend：SQLite，路径 `/app/storage/mlflow.db`（容器内）
- 配置：`MLFLOW_TRACKING_URI=sqlite:////app/storage/mlflow.db`
- 用途：每个 V3 ExperimentRun + V2 TrainingTask 在训练时自动 `mlflow.log_*`：
  - `params`：完整超参
  - `metrics`：训练 / 验证 / 测试集指标，含 step（用于 epoch / fold 折线）
  - `artifacts`：模型文件 + 输出图（如启用 mlflow autolog）
- 访问：可外接 `mlflow ui --backend-store-uri sqlite:///storage/mlflow.db --port 5000`

> **MLflow 与 V3 表的关系**：V3 把核心指标快照写到 `experiment_runs.metrics` JSON（用于 leaderboard / inspector），同时把全量 step 序列写进 MLflow（用于 autolog 兼容、第三方导出）。两者是**冗余**，以 V3 表为权威。

## 5. 本地文件系统

容器内路径 `/app/storage/`（宿主机仅 dev 模式挂载）：

| 路径 | 内容 | 是否挂卷 |
|---|---|---|
| `storage/uploads/{uuid12}-{name}` | 上传的原始数据集 | **否**（容器重启即丢，需启 S3_ENABLED） |
| `storage/models/{task_id}.joblib` | ML 模型 | 否（同上） |
| `storage/models/dl_{task_id}.pt` + `.pt.scaler.joblib` | DL 模型 | 否 |
| `storage/logs/{task_id}.log` | 纯文本日志 | 否 |
| `storage/logs/{task_id}_metrics.json` | step-by-step metrics 快照 | 否 |
| `storage/mlflow.db` | MLflow SQLite | 否（与 mlruns/ 一起会丢） |
| `mlruns/` | MLflow artifacts 目录 | 否 |

> 生产环境应当 **始终** 设置 `S3_ENABLED=true`，所有上述目录的写入会同步上传到 MinIO，本地仅作为热缓存。

## 附：从 V2 到 V3 的兼容映射

| V2 概念 | V3 对应 | 桥接方式 |
|---|---|---|
| `training_tasks.id` | `experiment_runs.id` | `experiment_runs.params.dataset_id` 复用 V2 `dataset_id`；`PlatformTask.payload_ref="train:{v2_id}"` 把孤立 V2 训练 wrap 成 V3 视图 |
| `training_logs` | 同表复用 | RunInspector 日志 tab 通过 `resolver.py` 在 `[run.id, payload_ref.legacy_id, platform_task.id]` 候选链中查找 |
| MLflow run | V3 也写一份 | `experiment_runs.metrics` 是权威，MLflow 用作 autolog 兼容 |
